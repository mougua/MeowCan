# 原版画面还原修改方案

## 1. 目标与执行约定

本方案依据 `ref/pics/` 的四张截图制定。目标是还原左侧罐体、表情、音符、连击、击中效果和结算画面。保留现有曲库、拖放和单机演奏功能。

调研日期：2026-09-10。本次只新增方案文档。已查看截图、现有 PNG、渲染及主控代码，并临时解包相关原始素材。尚未运行浏览器进行现版截图比对。下文区分代码事实、素材事实和待校准参数。

执行原则：遵循 SOLID 和 KISS。每次只完成一个任务包。优先使用原版图像，避免重新绘制。保留音频时钟、判定窗口、谱面解析和音符候选池。`ref/` 始终只读。

## 2. 差异与原因

| 项目 | 原版截图 | 当前实现及原因 | 修改方向 |
| --- | --- | --- | --- |
| 跑道背景 | 保留罐口弧线、笑脸和七轨线 | `setupScene()` 将背景 `(0,34,198,270)` 拉成 `198×300`；表情未加载 | 恢复自然尺寸，再对齐裁剪范围 |
| 整体比例 | 截图为左侧局部，且裁剪不同 | 场景 `716×516` 分别缩放到 `800×600`，横纵比例不同 | 统一等比缩放和输入坐标转换 |
| 按键 | 位于罐内底部，呈浅 U 形排列 | 全部放在 `y=480`，罐框却结束于 `y=468` | 使用逐键坐标，并同步点击区域 |
| 上方装饰 | 有带眼睛的翅膀角色和黄色星形角色 | 未加载相关角色图集 | 加载 `image/star/` 资源 |
| 音符 | 白色扁底座上有心形图案 | 只加载 `note_skin0.png`，缺少底座 | 默认使用 `note_base1` 与 `note_skin1` |
| 连击 | 大号数字位于跑道上部中央；截图出现数字 1 | 放在 PDA 下方；缩小至 0.65；`combo<=1` 隐藏；额外显示 COMBO | 移入跑道并支持 1 连击 |
| 击中 | 判定线附近出现粉色闪光颗粒 | 仅加载 `hitani0_0`，统一缩至 0.65；长按也重复用短音符爆光 | 校准帧图、锚点与长按专用效果 |
| 结果 | 罐内显示 Result、分数、心形、RATIO 和 EQ | 曲终只停止运行和音频 | 新增结算视图及状态切换 |
| 失败 | failed、鼓励文字、悲伤脸、星形眩晕表情 | 没有失败分支；生命为 0 也继续运行 | 单独实现失败展示与触发规则 |

## 4. 按顺序执行的任务包

### P0：恢复素材导出与确定性预览

**文件**：新增 `web/scripts/convert_assets.js`，新增 `web/src/game/skin.ts`；新增开发专用预览入口。

1. 按 `docs/spec/asset-formats.md` 实现 RGB565、vlle 和 vifont 解包。先支持本方案所需文件，不开发通用资源管理框架。
2. 输出至 `web/public/assets/classic/`。保留来源路径、图像尺寸、色键和字模头元数据。允许重复执行，产物应一致。
3. 检查数据越界、非法跨度及解码后的字节消耗。不能跳过解码错误继续输出损坏图。
4. 生成带文件名和帧号的联系表。为不规则图集建立显式裁剪表。矩形边界不得截断阴影。
5. `skin.ts` 集中保存纹理路径、裁剪帧、音符尺寸、颜色索引和布局常量。先支持一种默认皮肤。
6. 开发预览由 `import.meta.env.DEV` 限制。支持固定时间、表情索引、七轨音符、连击值、击中帧和模拟结果。预览不依赖音频解锁或完整歌曲。

**验收**：能同时查看两种底座及其叠加效果；能按帧检查角色、表情和结果文字；所有裁剪范围合法。

### P1：修正布局和输入映射

**文件**：`renderer.ts`、`skin.ts`、`main.ts`、`index.html`。

1. 保留 `716×516` 为逻辑舞台。建议画布也采用该尺寸，页面改用 `716 / 516` 比例。若必须保留 `800×600`，则等比缩放并居中留边。
2. 保持罐框和跑道的自然尺寸。移除当前跑道局部拉伸。先只显示背景、罐体和判定线。
3. 用纹理上的弧线和边缘校准位置。当前 `PLAY_X=40`、`PLAY_Y=140` 只是起点，不能视为原版坐标。
4. 明确 `judgeY` 表示判定接触线。音符底部、击中中心和按键坐标都引用同一布局配置。
5. 按键改为 7 组独立矩形，呈浅 U 形分布。用相同矩形绘制按键和检测点击。核对 key_base 与 key_normal 的叠放，再接入 key_put。
6. 封装 `clientToScene()` 与 `hitTestKey()`。移除 `main.ts` 中固定 `y=480..504` 的判断。留边区域不响应按键。
7. 图层顺序建议为：全局背景 → 跑道及表情 → 长按条和音符 → 击中效果 → 罐框与按键 → 上方角色 → 连击及结果 → 页面交互。
8. 跑道遮罩仅作用于需要裁切的内容。连击和结果使用独立容器，避免误裁掉标题与阴影。

**验收**：罐口不重影，背景无纵向拉伸；轨道中心与判定槽对齐；按键位于罐内。桌面和窄屏均能点中全部 7 键。

4. 把音符宽、高、接触点偏移改成配置。移除头尾固定 `height=24`，及长按连接点中与高度相关的 `+12` 魔数。
5. 建议所有头尾采用底部中心锚点。下落公式计算底部接触点，使 `startSec` 时准确接触判定线。
6. 保留已有长按状态与候选池。调整长按条的头尾连接，确保换皮肤不改变持续时间。
7. 截图存在红色和紫色图案，但不能据此证明完整轨道配色。先保留当前索引表，并将配色标为待校准。

**验收**：七轨都有白色扁底座及完整心形。头尾不拉伸，长按条不悬空。调速和重开后无残留音符。

### P3：恢复笑脸和上方角色

**文件**：`renderer.ts`、`skin.ts`。代码较多时新增 `stage-decoration.ts`。

1. 加载表情单帧，先完成静态笑脸。让帧内轨道线与背景轨道线逐条重合。
2. 选择与底图一致的 face_map 版本。禁止通过任意透明度掩盖接缝。
3. 加载粉色翅膀角色与黄色星形角色，按截图校准罐口附近的位置。上方角色不受跑道遮罩影响。
4. 先实现明确状态：演奏显示笑脸；结果显示截图对应表情；失败显示悲伤和眩晕。低生命阈值及命中眨眼属于可选增强。
5. 若未确认 ANI 格式，先提供静态帧。后续动画参数集中配置，并标为复刻近似值。

**验收**：笑脸位置正确，无矩形接缝和双轨线；上方角色完整可见；重开恢复演奏表情。

### P4：恢复连击与击中效果

**文件**：`renderer.ts`、`skin.ts`，必要时新增 `hit-effects.ts`。

1. 将连击移至跑道上部中央。参考 `can-combo.png`，不再显示截图中不存在的 COMBO 标签。
2. 连击 0 隐藏，1 开始显示。按所有数字的实际宽度整体居中，验证 1、9、10、99、100、1000。
3. 核对 default/combo.ift 与现有 combo.png。优先使用匹配截图的原版字模。先保留自然尺寸，再通过配准决定缩放。
4. 预览每套 hitani。选择最接近截图粉色闪光的素材，记录帧数、帧尺寸和接触锚点。
5. 当前 hitani0_0 使用 10 帧，每帧 80×118。该规则仅适用于已确认的这张图，不能套到其他图集。
6. 长按使用专用动画，每条活跃长按最多一个持续效果。避免每 0.1 秒创建一组短音符爆光。
7. 普通击中 Sprite 改为复用池。动画结束后隐藏并回收，清空时重置全部状态。
8. 效果计时使用独立 `deltaSec`。当前计时依赖歌曲时间，曲终停止后无法继续消退。音符位置仍使用音频主时钟。
9. 当前大号 COOL/GOOD 文本缺少这组截图的外观依据。将其设为可配置，避免遮挡连击。保持原有判定逻辑。

**验收**：1 连击可见；多位数始终居中；七轨击中在各自判定槽上出现；30、60、144 Hz 下动画持续时间一致。

### P5：实现结果与失败展示

**文件**：新增 `web/src/game/result-view.ts`；修改 `main.ts`、`renderer.ts`、`skin.ts`。

职责边界：主控决定何时结束；结果视图只接收数据并绘制。不要让视图直接修改判定引擎。

建议最小接口：

```ts
type RoundState = 'ready' | 'playing' | 'result' | 'failed';
interface ResultData {
  outcome: 'result' | 'failed';
  score: number;
  accuracy: number;
  maxCombo: number;
  eq?: number;
  multiplier?: number;
}
// ResultView: show(data), update(deltaSec), hide(), reset()
```

1. 裁出 Result 和 failed 字样，放在罐体上部。保留罐体背景、按键及判定线。
2. 分数使用 `0_Score.ift`。截图为五位补零，初始采用至少 5 位；高分不得截断。
3. 使用图集中现成的心形、RATIO/EQ 线框及文字。组件位置单独配置，避免缩放整个图集。
4. 裁出 failed 截图对应的鼓励文字。失败时显示悲伤脸及眩晕星形。
5. 曲终沿用现有 `durationSec + 2` 作为初始触发点。先核对最长长按尾与音频尾音，防止提前结算。
6. 添加幂等 `finishRound(outcome)`。同一局只执行一次。保存分数快照，关闭演奏输入，清理按键和长按音源，停止伴奏，再显示结果。
7. 注意 `releaseInputs()` 会调用抬键处理，可能改变长按得分。结算清理应支持取消输入而不追加判定，避免清理动作污染快照。
8. 停止演奏后继续更新结果动画。不要将全部界面更新包在 `isRunning` 条件中。
9. 失败触发采用明确的初始产品规则：生命降至 0 时进入 failed。这是本次实现建议，并非已验证的原版机制。可保留一个继续练习配置。
10. 重开、换歌、拖入谱面都必须隐藏结果、取消旧局输入和音频、清除旧效果，然后进入新局。异步加载完成时避免恢复旧局状态。

**数据限制**：当前 `GameScore` 没有 EQ 和倍率字段。截图中的 RATIO 也不能直接证明等于现版 accuracy。禁止硬编码截图中的 `1768418` 或 `×4` 为真实成绩。

第一版在原版 RATIO 区域显示现版 accuracy，并在此方案的完成记录中注明语义差异。EQ 无数据时显示占位符；倍率无数据时隐藏。`×4` 可由开发预览注入，用于验证素材和布局。原版计分、EQ 及倍率公式另开任务研究。

**验收**：能通过预览分别展示两张结算画面；实际曲终和生命归零只触发一次；结果显示后分数冻结；重开正常发音且无旧局残留。
